**What this is:** metadata only — footprints, times, angles, pixel scales, URLs — for orbital images whose footprint overlaps a
10 km × 10 km square around each of the four current sites. **No image was downloaded** except ≤ 20 ODE thumbnails for a
pipeline test (dev images only, cached, not committed). Sun azimuth/elevation are JPL Horizons values at the site centre at the
image's mid-time, used **for stratification only**. All values are SOURCE-BASED · UNVALIDATED.

**Format:** `catalogue.csv.gz` stands in for `catalogue.parquet` because the project venv has no pyarrow/pandas and installing
into a shared venv during a parallel night run was not a conservative step. Columns: `imagery/catalogue.schema.json`.
Provenance (every ODE and Horizons response SHA-256): `imagery/catalogue.provenance.json`.

## Checks run
- ODE's `Footprint_SP_geometry` frame = `science/frames.py` (x = ρ sin λ, y = ρ cos λ, R = 1737.4 km): every vertex of a recorded
  TC footprint matches within 2 m (`tools/imagery/tests/test_geometry.py`).
- Every ODE query: unique products fetched = ODE's count (one query returned a product twice across a page boundary; deduplicated).
- Sun az/el wrapper vs the committed bundle `data/bundles/site04_roi3_2026-11-14_14d_mast1m.json` (same Horizons convention,
  5 samples): max |Δaz| = 4 × 10⁻⁹°, max |Δel| = 7 × 10⁻⁷° (the bundle's observer is 1.7 km higher).
- Rebuilding the catalogue from the cached responses gives the same SHA-256.

## Known gaps
- **Sub-spacecraft position is not in the catalogue.** ODE does not return it. ShadowCam PDS4 labels have it
  (`geom:subspacecraft_latitude/longitude`, `geom:spacecraft_target_subspacecraft_distance`; checked on M013371158SC). LROC CDR
  PDS4 labels do **not** (checked on M101350392LC); it is in the LROC EDR index tables. Kaguya TC labels: not checked (DARTS
  rejected the request). The label URL is in every row; positions will be read per image when a render twin is built (§6.2).
- **ShadowCam coverage is unverified.** ODE's ShadowCam footprints are the browse map's extent ("Footprint from corresponding
  browse-calibrated-map"); their estimated strip width is ~60–175 km against a ~5.4 km swath, so nearly every ShadowCam row is
  `footprint_suspect` and the ShadowCam "kept" counts are an upper bound. A true footprint needs the label's corner coordinates or
  the product's valid-data outline (per-image fetches; not done tonight). The protocol gates suspect rows out of scoring.
- `footprint_suspect` (strip-width test) needs a pixel scale; 3 WAC rows with ODE pixel scale 0 are unassessed.
- Kaguya TC pixel scale is the instrument nominal 10 m/px (ODE gives none).
- Terrain type is one label per site, not a map.
- Strata are fine-grained, so many strata hold one image; the held-out rule (systematic sampling over the stratum-sorted list)
  keeps 30 % overall and per stratum ± 1.
