# PGDA 69 comparison, float64 rerun (E1, 15 Nov 2026)

SOURCE-BASED, UNVALIDATED. This is the polaris_batch v2 PGDA 69 comparison (the 18.6-yr average Sun and Earth visibility map) rerun with `core.Dem.open` reading heights as float64. That is the only code change (`code/core_float64.patch`). The windows, DEMs, 1 m near-field step, 1 m mast and the 210 cached JPL Horizons responses are unchanged, and the inputs and commands are in `manifest.json`. The fix barely moves the ROI comparison. Using the same 1 m step for both, the float32 run of this code on the Mac gave Sun ρ 0.431, bias +3.68, RMS 10.08 pts and Earth ρ 0.885, bias +2.94, RMS 4.27 pts (fine variant, 17 ROIs). The float64 run gives **Sun ρ 0.439, bias +3.90, RMS 10.12 pts** and **Earth ρ 0.885, bias +2.98, RMS 4.33 pts**: differences of +0.008 ρ, +0.22 bias and +0.04 RMS for Sun, and 0, +0.04 and +0.06 for Earth. The coarse (80 m only) variant is unchanged to within 0.01 (Sun ρ 0.488, +4.99 / 10.95; Earth ρ 0.887, +3.15 / 4.58). The 21 × 21 grid does not change either (fine, float64 vs the committed `data/batch/2026-11-14/README.md` §5 table): Sun ρ Site01 0.787 → 0.786, Site04 0.927 → 0.927, Site07 0.715 → 0.714, Site11 0.740 → 0.737; median |d| 2.9 → 2.96, 3.2 → 3.25, 3.4 → 3.35, 3.0 → 3.03 pts; Earth ρ 0.939 → 0.941, 0.862 → 0.860, 0.900 → 0.900, 0.981 → 0.982. These grid "old" values come from the 2026-11-14 run, which also differed in near-field step (that README says 5 m for the PGDA 69 jobs). A float32 control at 1 m was started and then stopped to keep within the deadline, so the grid deltas mix precision with step. Conclusion: the float32 bug that moved the 14-day Site04 RoI 3 numbers (93.77 → 94.36 %) has a negligible effect on the 18.6-yr PGDA 69 agreement. The README §4 values (Sun ρ 0.505, +4.0 / 10.1, from the 5 m step run) are superseded by `rois/summary.json` here.
